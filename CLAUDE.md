# Kombu - Creative Studio Website

## Overview
Multi-page studio website for Kombu (kombu.uk), Ryan's one-person creative studio in Southampton: web design, graphic design, commercial photography, and marketing & infrastructure. Linen tray theme: warm ink outlines around four compartment fills (terracotta, kelp, ochre, mist). Anti-agency positioning, first person singular ("I", never "we"), British English, no em/en dashes anywhere in copy or aria-labels. Never mention AI tooling on the site. Wording: the site calls Kombu a "studio" ("one-person creative studio", "Studio partnership"); Ryan confirmed on 25 September 2026 that this stays. The 11 September "creative service, not creative studio" instruction applied to the advert voiceover only.

## Tech Stack
- **Framework**: Astro 5 (static output). No View Transitions, no `<ClientRouter />`; each page is a full navigation.
- **Animations**: Lenis only (CDN, `is:inline`), for scroll smoothing. No GSAP, no ScrollTrigger, no shader. The home page's one authored moment is the wordmark landing on load: each letter settles in turn (`home-land` in `src/styles/home-preview.css`). There is no pinned or scroll-driven intro any more. It was retired on 8 September 2026 when the opening was rebuilt as a static, content-height layout, because a pinned stage has to fit the fold on every viewport and needed a fresh patch for each screen size. The old pinned-intro sequence in `Layout.astro` still exists but is inert without `#intro`. `prefers-reduced-motion` and the `?nomotion` query flag both add `.no-motion`, which freezes the letter landing, the example-tile hover, the portrait parallax and the recorded work previews, and forces lazy images eager for static captures.
- **Styling**: one stylesheet, `src/styles/site.css`, imported by `Layout.astro`. CSS custom properties for all colours; never raw hex inside rules. No shadows, no gradients: elevation is a 2px ink outline on every card, tile, pill and image frame, and a hover is a 2px downward translate.
- **Fonts**: Supermassive RS (display, self-hosted, `/fonts/SupermassiveRS-{I,II,III}.woff2` at weights 700/800/900) + Switzer (body) from Fontshare. Supermassive RS is Ryan's own licensed cut of Supermassive, made with the original author's permission, with custom-drawn punctuation, so it covers the full character set and needs no fallback face and no `unicode-range`. Bevellier has been removed from the system entirely. The superseded trial files (`Supermassive-*.woff2`) stamp a rotated "TRIAL" watermark over every non-alphanumeric glyph, so if punctuation renders as a tiny rotated word, the wrong file is loaded.
- **Mark**: the brand symbol is a four strand knot in the four compartment colours, added 11 September 2026. It is used only as the favicon and app icons (`public/favicon.svg` plus the PNG, ico and maskable set, all versioned `?v=3`); on the page the identity stays the KOMBU wordmark. Master artwork is outside the repo at `Google Drive/Design/Kombu Logos/New-SVG.svg`. The JSON-LD `logo` field points at `/favicon-512.png`, so it now carries the mark too.
- **Deploy**: primary is the `cf-pages-deploy` MCP (`deploy(project_dir="/Volumes/External 2TB/Websites/Website Site/dist", project_name="kombu-web-design")`); fallback if the MCP is unavailable is `wrangler pages deploy ./dist --project-name=kombu-web-design --branch=main --commit-dirty=true` (branch=main is production). No git auto-deploy.

## Architecture notes
- `src/layouts/Layout.astro`: the whole document. Head carries meta/OG/Twitter/geo/PWA/favicons and the JSON-LD base graph (WebSite + ProfessionalService/LocalBusiness + Person) merged with each page's `extraSchema` prop, same props interface as before (`title`, `description`, `canonical`, `ogImage*`, `ogType`, `extraSchema`); body carries every client script (Lenis bootstrap, the legacy pinned-intro sequence which is inert now that the home page has no `#intro`, mobile menu and lightbox) plus the service worker registration. `<slot name="head" />` lets a page add its own head content (the photography page uses it for the Google Places script). A noscript block forces the floating nav visible and collapses the pinned intro's scroll padding, mirroring what `.no-motion` already does, since without JS the nav would otherwise sit permanently at `opacity:0`.
- No separate runtime component: `SiteRuntime.astro`, `Rail.astro`, `BottomNav.astro` and `Loader.astro` are retired. Navigation is `Nav.astro`, a single floating pill nav shared by every page (desktop and mobile alike): white, 2px ink outline, the wordmark left, links centre, a WhatsApp pill right; under 768px the links collapse behind a Menu pill that opens a full-screen tray menu (six filled tiles on linen, the four compartments plus an ink Work tile and a white About tile, contact pills centred beneath). `Footer.astro` is the shared ink lid at the bottom of every page.
- The quote calculator lives inline in `photography.astro` (no separate `QuoteCalculator.astro` component): same pricing logic as before (RACK 2h £275 / 4h £415 / 8h £690, takeaway x1.25, multi-day x0.9, local independent x0.8 only when a verified distance <=30mi and not London, travel bands £0/£40/£90/£150, London £80, round to £5). London text-detection only applies to postcode-shaped input; coordinates use the bounds check. Maps key is referrer-restricted to kombu.uk + localhost.
- Shared interior-page components: `PageHead.astro` (the opening full-width fill card under the nav, h1 + lede + fact chip + two pills + an image or collage), `Ledger.astro` (ruled plain-label rows, not cards), `Faq.astro` (native `details`/`summary` accordion, no JS), `ContactCard.astro` (the ochre contact card, WhatsApp/call/email pills), `Marquee.astro` (clients marquee).
- Portfolio/work cards: home shows three; `/web-design` shows eight. `WorkPreview.astro` renders 1080x750, 60fps recordings of a 1440x1000 desktop viewport from `public/videos/work/<slug>.mp4` with matching `.webp` first-frame posters. `public/work-previews.js` plays the nearest visible preview on mobile (up to three on desktop), pauses offscreen, and honours the shared Pause previews control, reduced motion and `?nomotion`. No iframe or screenshot panning is used. `npm run capture:work -- padharo` refreshes an individual recording from its live site; capture in sRGB and inspect the full video, its loop and all stopping points before deploying. Never take browser screenshots while native recording is active, because this can resize the capture surface. The capture command checks every output frame for the grey-canvas fault.
- Case studies (`src/pages/work/`) share `src/styles/work.css` (imported by those pages only, like `home-preview.css`) and `public/case-study.js` (the opening film, the swipe strips' Back/Next and count, story loops that play only while on screen, and the full-screen viewer). Assets live in `public/images/work/<client>/` and `public/videos/work/` (`<client>-promo-{wide,tall}` plus `.webp` posters, `padharo-story-*`, `mustang-phone`, `mustang-group`, `ennios`). The promo films are made in HyperFrames outside the repo, at `/Volumes/External 2TB/Videography/Kombu/case-study-promos/` (the `promo-film` skill); web encodes come from its `web-v2/` folder. Each section of a case study ends with an onward link to its discipline page, and the case studies link each other. The two case-study phone and desktop recordings of the Mustang preview were made with a CDP screencast script, not `capture:work`. Every fact on these pages carries a source; the confidential list (fees, analytics figures, dashboard data, private praise) stays off them.
- `?nomotion` query param renders any page statically (used by screenshot tooling), same as before.
- Clay props (27 Sep 2026): `Clay.astro` renders one of Kombu's clay illustrations from `public/images/clay/` (the speech bubble on every contact card, the magnifier on /web-design's free review, the stethoscope on /marketing's Health Check, the floppy on /404). Placement lives in the "Clay props" block at the end of `site.css`, per width band; props anchored to a heading word sit in an empty `.clay-at` span glued to that word with `.clay-glue`, and `.br-phone` breaks only apply on phones. See DESIGN.md "Clay prop". Ryan places them himself with the dev-only arranger: add `?arrange` to any page under `npm run dev` and it opens `dev-tools/arrange.html` (device frames for 390/412 phone, 820 tablet, 1280 laptop, 1920 wide, with undo, per-item reset and Copy all); the engine is `dev-tools/clay-arranger.js`, inlined by `Layout.astro` only when `import.meta.env.DEV`, so it never reaches `dist` (grep `dist` for `clay-arranger` before deploying). Saves go to localStorage `kombu-clay-arrange-v3`; bump the key after each bake so old moves don't replay on the new layout. His round-1 and round-2 exports are in `_backups/2026-09-27-clay/ryan-arrange/`.

## Client quotes: quotes.kombu.uk (separate Pages project)
Private, `noindex` quote documents live in `quotes/<slug>/index.html` and deploy to their **own** Cloudflare Pages project `kombu-quotes` (custom domain `quotes.kombu.uk`), NOT to the main site. Keeps client pricing off kombu.uk and gives each quote a clean URL like `https://quotes.kombu.uk/toqeer/`.

- `build-quotes.mjs` assembles `dist-quotes/` = `quotes/**` plus the shared brand fonts (`public/fonts`) and favicons, so the fonts are never duplicated in the repo. `dist-quotes/` is gitignored.
- `quotes/_redirects` sends the bare subdomain to kombu.uk (there is no quote index); `quotes/robots.txt` disallows everything.
- Quote pages are standalone single-file HTML using the same tokens as the site: Supermassive RS display (uppercase, 800, no fallback face needed), Switzer body, terracotta accent, 8/12/16px radii, and a nine-step type ramp declared in `:root`. Type rules follow the site exactly: h1 line-height 0.8, h2 0.87, h3 0.88, body and links Switzer 300 at 16px. Sticky section headers are only for grid layouts where the heading column sits beside scrolling content, never on full-width headers.
- `public/nova-quote/` stays on the main site because that link was already sent to the client; new quotes go to the subdomain only.
